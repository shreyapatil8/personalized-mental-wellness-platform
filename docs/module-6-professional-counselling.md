# Module 6 — Counselling

Students book fixed 30-minute future slots; partial unique student/slot and counsellor/slot indexes prevent active collisions. Assigned counsellors approve/complete/cancel; students can cancel their own active appointments. Legacy indexes require an operator audit.

GET /api/counselling/appointments lists owned appointments. PATCH /:id/status changes status; PATCH /:id/notes saves counsellor-private notes plus shared progress. Students never receive the private-note field. Only approved/completed appointments permit session notes.

GET /:id/summary gives a factual overview/cached generated briefing; POST generates a briefing through the local Ollama service. Both require an active appointment, the assigned counsellor, profile consent and appointment sharing. PATCH /:id/sharing lets the student change sharing. Provider generation rechecks consent before returning/saving. If local Ollama is unavailable, generation returns an error rather than an invented briefing. Full journal passages and chat transcripts are not returned in factual overviews.

The AI-Assisted Pre-Session Briefing appears separately from factual records in appointment management and before chat in the counsellor's session view. The counsellor uses Generate AI briefing; a current cached draft is shown with local-generation attribution and its date. The existing Wellness Intelligence Engine uses a counsellor purpose to reserve the valid structured Initial Wellness Assessment as the primary baseline. Its normal concern relevance, recency, source limits, token budget and deduplication select supporting evidence using both the appointment category and student booking note. Relevant optional assessment notes are permitted by both sharing gates (the assessment question explicitly invites information for the counsellor). Supporting sources are relevant profile/goals, recent mood patterns, WHO-5 check-ins, journal themes and a currently valid non-diagnostic ML estimate. Journal passages/titles, private assistant conversations and private counsellor notes are excluded from the provider request and overview.

Generation requests one or two paragraphs, at most 180 words, using dated student-reported language without diagnoses. The local Ollama service and appointment digest/invalidation mechanisms are reused. A changed concern, note, selected evidence or generation instructions invalidates the draft; consent/evidence are rechecked after generation. The visible overview also refreshes every minute and on focus. Missing assessment/evidence, unavailable provider, generation failure and denied consent remain explicit states. No database migration is needed.

Optional /api/documents routes support explicitly shared PDFs, authenticated Cloudinary storage, participant ownership and 60-second signed downloads. A closed appointment revokes counsellor access; already-issued links may remain valid until expiry. Full deletion by the student removes the provider asset first. Live provider verification remains required.
